在之前的实验中，我们在单向（生产者-->消费者方向，即生产者生产数据后，消费者主动到队列拉取数据）上实现——这种模式，我们称为拉模式（即消费者主动去拉取它们需要处理的数据）。

现在存在一种需求，生产数据速度是可变的，当一旦有数据生产时，能否立即通知到消费者，让消费者立即处理对应的数据？——这种模式，我们称为推模式（也称发布--订阅模式）。


在实验《Socket下的生产者-消费者模型实现》中进行改进：

1、消费者启动后，首先到队列系统（在本实验中可改称为消息队列）中注册，等于告诉队列，一旦有消息，就立即发送给我；

2、生产者生成数据，这个和以前实验一样；

3、消息队列收到生产者发送过来的数据后，根据步骤（1）所订阅的消费者列表，逐个向已订阅的消费者发送此数据（本实验先采用广播消费模式，即每个订阅者都能收到同一队列的全部消息）；

4、独立为三个exe，首先必须启动消息队列的exe，其次启动消费者，最后启动生产者；

5、本实验暂不考虑消息缓存（持久化），即消息队列接受到生产者消息后会保存到数据库中；

6、本实验需自己编写，不能用现成的第三方中间件例如RocketMQ、RabbitMQ、eMQ等。
